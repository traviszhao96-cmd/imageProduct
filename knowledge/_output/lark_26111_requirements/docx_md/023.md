## 背景与目标

### 2.1 用户问题

- 当前默认 H.264,同画质下文件体积比 H.265 大约 30%,用户存储被无意义地多占用。
- 当前编码逻辑对用户不透明且不自洽: 

  - 用户手动选择 H.265 后,视频、慢动作、延时按 H.265 录制;但视频开滤镜、或使用前后双录(预览录屏链路)时,实际输出静默回落为 H.264——用户选了 H.265,拿到的却可能是 H.264 文件。
  - 默认 H.264 下开启 HLG 时,系统因 10-bit 依赖自动切换为 H.265——系统已默认 H.265 是更高能力的编码,默认值却停留在 H.264。

### 2.2 行业现状

- iPhone、三星、Pixel 等主流厂商均已默认 HEVC/H.265 多年,是行业共识性默认选择。
- 2026 年当下,主流平台与设备对 H.265 的解码与分享支持已普及,兼容性风险基本消除。

### 2.3 用户目标

- 不做任何设置,即获得同画质、更小体积的视频文件。
- 自己的编码选择在任何模式下都被一致执行,不出现静默回落。

### 2.4 产品目标

- 26111 / 26121 新机型出厂默认编码改为 H.265。
- 编码设置在全部视频相关模式下一致生效,消除链路差异导致的编码不一致。



## 功能定义

### 3.1 功能名称

视频默认 H.265 编码

### 3.2 一句话描述

新机型视频默认编码由 H.264 改为 H.265,并使编码设置在所有模式(含滤镜、前后双录等录屏链路)下一致生效。

### 3.3 范围

**范围内**

- 项目范围:26111 / 26121 首次上项,新机型出厂默认生效,无项目差异。
- 模式范围:视频、慢动作、延时摄影、前后双录,以及视频叠加滤镜 / tuning 的场景。
- 设置项保留:H.264 / H.265 可手动切换,选择永久记忆。
- 录屏链路改造:滤镜、前后双录等预览录屏链路改为跟随用户编码设置。

**范围外**

- 老机型 OTA:存量机型不修改默认值,维持现有行为。
- 编码码率标定与分布优化(另行跟进)。
- 照片格式(HEIF 等)。



## 设计稿

无 UI 变更,沿用现有编码设置项,无设计稿依赖。



## 需求

### R1 · 默认编码变更为 H.265

- 26111 / 26121 出厂默认编码为 H.265。
- 设置中保留 H.264 / H.265 选项,位置与现状一致。
- 用户切换后永久记忆,不随重启相机/设备、模式切换、版本升级重置。
- 老机型不随 OTA 变更默认值。

### R2 · 编码设置全模式一致生效(录屏链路改造)

- 用户设置的编码格式在全部模式范围内一致执行: 

  - 正常录制链路(视频 / 慢动作 / 延时摄影):按用户设置编码。
  - 预览录屏链路(视频开滤镜 / tuning、前后双录):本期改造为同样按用户设置编码,不再固定回落 H.264。
- 仅改变编码格式,不改变分辨率、帧率、码率档位等其他规格;音频编码不受影响。

### R3 · HLG 联动逻辑维持现状

- 用户手动选择 H.264 且开启 HLG 时,自动使用 H.265(10-bit 依赖),无额外提示,行为与现状一致。

## 指标与验收

### 8.1 成功指标

- 新机型开箱默认 H.265,无需用户操作。
- 用户编码选择在全部模式范围内一致生效,不出现静默回落。
- 同场景下 H.265 文件体积较 H.264 明显减小,画质无可感知劣化。

### 8.2 验收标准

| **#** | **验收项** | **预期结果** |
|-|-|-|
| 1 | 新机开箱默认编码 | H.265 |
| 2 | 视频 / 慢动作 / 延时录制 | 输出编码与用户设置一致 |
| 3 | 视频开启滤镜 / tuning 录制 | 输出编码与用户设置一致(默认 H.265) |
| 4 | 前后双录录制 | 输出编码与用户设置一致(默认 H.265) |
| 5 | 手动 H.264 + 开启 HLG | 自动 H.265 |
| 6 | 切换编码后重启相机 / 设备 | 选择保持 |
| 7 | 同画质码率对比 | H.265 较 H.264 节省约 30% |
| 8 | 老机型 OTA 后 | 默认值与编码行为不变 |
