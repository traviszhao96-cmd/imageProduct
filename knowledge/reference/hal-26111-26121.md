# 26111 / 26121 HAL 软件设计摘要

> 来源: `26111&26121 HAL软件设计方案.pdf`
> 文档生成时间: 2026-07-13
> 知识库整理时间: 2026-07-13
> 适用范围: 26111 / 26121 Camera HAL、算法链路、项目 FL 能力判断

## 使用规则

- 本文描述 HAL 已设计或明确规划的通路、模式、规格和依赖。
- HAL 能力不自动等于产品最终开放能力。只有明确到项目、模式和摄像头的内容，才能作为 FL 的支持证据。
- 文档中的“评估”“待确认”“根据产品需求实现”不应写成 FL 的 `✓`，应保留为 `TBD` 或争议项。
- 本文优先级高于基于 25111 / 25131 继承关系做出的旧推断；PRD 已明确裁剪或取消的产品功能仍以 PRD 为准。

## 1. 项目硬件基线

| 项目 | 26111 | 26121 |
|---|---|---|
| SoC | SM7635 | SM7750 |
| 平台视频能力 | 4K30 | 4K60 |
| 前置 | OV32D, 32MP, FF | KD1, 32MP, FF |
| 主摄 | S5KHP5, 200MP, PDAF, OIS | IMX896, 50MP, PDAF, OIS |
| 超广角 | OV08J10, 8MP, FF | IMX355, 8MP, FF（继承项目配置；HAL 模式图包含 UW） |
| 长焦 | 无 | JN5, 50MP, 3.5x, PDAF, OIS |
| 内存/存储 | DDR4X 6GB/8GB, UFS 2.2 | DDR5X 8GB, UFS 4.0 |

26111 主摄的 HAL 物料表明确标注 OIS。此前“HP5 无 OIS”的结论应废弃。

| 后置夜景 | 0.6x-10x | 0.6x-10x | 与照片链路结构一致，差异主要是合成帧数与曝光时间；6GB 策略将夜景降为 7 帧 |

| 双景录像 | 前后各一路 1080P30 | 前后各一路 1080P30 | HAL 明确同时打开前后视频模式并在同一画幅预览/录制；产品交互以 Dual View PRD 为准 |

### 后置视频规格与 HLG

| 项目 | 规格 | HLG ON | HLG OFF |
|---|---|---|---|
| 26111 | 1080P30 / 4K30 | sensor normal mode | sensor stagger mode |
| 26111 | 1080P60 | 不支持 HLG | sensor normal mode |
| 26121 | 1080P30 / 4K30 | sensor normal mode | sensor stagger mode |
| 26121 | 1080P60 / 4K60 | sensor normal mode | sensor normal mode |

这张表确认的是项目级 HAL 通路。FL 仍需 SE 按 Main/UW/Tele/Front 分别确认规格入口，不能直接把所有摄像头都标成支持。

录像滤镜仅支持 1080P30，走 APP 录屏特效链路。26111 录像中拍照仍在评估功耗与画质，尤其需要确认 6GB 机型可行性。VSS 评估已取消。录像中前后镜头切换采用硬切。

## 3. 后置照片算法链路

后置照片包含以下 snapshot usecase：

| Usecase | 算法 | 典型取帧 |
|---|---|---|
| c0 | TF Super Night | NZSL 8 帧 |
| c1 | TF HDR | ZSL + NZSL/PSL 7 帧 |
| c2 | TF SR | ZSL 5 帧 |
| c3 | MFNR | ZSL 5 帧 |
| c4 | Motion Capture | 项目策略 |
| c5（部分模式编号为 c4） | HDSR | HDR + SR 条件组合 |

通用后处理链路包含 CFR、LDC、FRT、美颜、滤镜、水印和 JPEG 输出。该链路说明这些模块可以被 usecase 调用，不代表每个模式或摄像头都默认开放对应用户功能。

### SAT、ISZ 与高倍变焦

- 26111 后置照片为 2SAT，26121 为 SAT；两者 HAL 均标注“无 Fallback 逻辑”。
- 26111 主摄亮度满足时，2x 预览切换到 in-sensor zoom setting；SM7635 平台不支持 seamless 切换。超广角不使用 ISZ。
- 26111 SR 输入：2x 使用 QBC RAW；4x 使用 hex / 4x4 RAW，并依赖外部软件 remosaic。6GB 机型的内存与性能必须专项评估。
- 26121 主摄和长焦亮度满足时切换 ISZ；超广角不使用 ISZ。
- AIGC 高倍链路仍处于评估状态。26111 需要确认 6GB 适配、外部算法数据、内存和性能；26121 文档也保留“AIGC 替换极感？”疑问，不能视为最终支持结论。

## 4. 人像链路约束

- 人像 depth 由主副摄单帧图计算，主副图亮度需要接近，不能直接使用多帧融合后的图像计算深度。
- 暗光下单帧噪声会影响虚化边缘，应作为人像夜景/暗光验收风险。
- 1x/2x 人像使用 Wide 主图 4096x3072，UW 副图 2400x1800 crop。
- 26121 3.5x 人像使用 Tele 主图 4096x3072，Wide 副图 2048x1536（1/2 binning + crop）。
- 进入 ISZ 区间后需要走 ISZ 对应的多帧链路，包括 ISZ MFNR 与 ISZ HDR。
- 这里的 UW 是算法内部 depth 辅助输入，不是用户可选择或可独立出图的摄像头；最终 FL 的所有人像模式行均应填写 `UW=✗`。

## 5. 高像素链路

### 26111

- HAL 定义主摄 Wide 单摄、1x、4:3、NZSL 高像素通路。
- 文档没有在该章节完整定义 50MP / 200MP / 200MP Ultra 的产品选项与切换逻辑；这些仍以高像素 PRD 为准。

### 26121

- 主摄与长焦支持高像素入口：1x / 3.5x、4:3。
- 50MP 不是单一 remosaic 路径，而是按亮度和动态范围选择四种链路：

| 场景 | Sensor 输出 | 算法 | 最终输出 |
|---|---|---|---|
| 高亮、低动态 | 直出 50MP | 平台 MMF（HAL 内实现） | 50MP |
| 中亮、低动态 | 12.5MP binning | TF MMF | upscale 到 50MP |
| 高动态 | 12.5MP binning | TF HDR | upscale 到 50MP |
| 低照 | 12.5MP binning | TF Super Night | upscale 到 50MP |

因此，KB/FL 中“26121 高像素全部使用 remosaic”或“50MP Ultra 只是 remosaic 后叠加 RAW HDR”的旧说明需要改写。产品选项名称和 Ultra 定义仍以最新版高像素 PRD 为准。

## 7. 需要进一步确认

### P0：会直接改变 FL 勾叉

1. 26111/26121 后置 1080P60、4K30、4K60 分别覆盖 Main/UW/Tele 哪些摄像头，SAT 是否在各规格生效。
2. 26111 主摄 OIS 是否已作为最终量产配置锁定；HAL 物料表与旧算法文档冲突，但与当前设备 YAML 一致。
3. 26121 高像素的 Main/Tele 产品入口是否都开放；50MP / 50MP Ultra 如何映射到四条 HAL 链路。
4. 26111 2SAT 的准确含义、支持模式，以及“SAT 无 Fallback”对 Macro Control / Fallback 功能的影响。
5. 26111 4x ISZ/SR 外部软件 remosaic 在 6GB 机型上的内存、性能和是否量产。
6. 26121 4K60 HLG 的最终产品开放范围。HAL 有通路，但需要功耗、温升和稳定性验收结论。

### P1：功能存在，但范围或产品定义未锁定

1. AIGC 高倍变焦是否最终量产，26111 的 6GB 适配和 26121 的替代方案分别是什么。
2. 前置 HLG 是否开放；HAL 写为“根据产品需求实现”，不能直接勾选。
3. 录像中拍照是否保留，26111 6GB 机型的功耗和画质结论是什么。
4. 4K Live / Motion Photo 是否量产；当前仅有专项评估链接。
5. 录像中前后镜头硬切的支持规格、音频连续性、文件连续性和 UI 限制。
6. 26121 Video Log 是否仍在项目范围；HAL 有专门链接，而旧设备配置将“视频 Log 模式”列为移除功能。
7. DCG 的功耗和画质评估结论。

### 文档自身需澄清

1. 部分通用链路图在 26111 页面包含 `T` 路径，但 26111 硬件没有长焦；应按硬件表裁剪，不可据图添加 Tele。
2. 26121 总焦段写 0.6x-120x，但算法分区示意图长焦横轴延伸到 140x；产品最大倍率需要统一。
3. 前置章节只列 1080P30/60，没有给出前置 4K 通路，与项目 P0“前置/广角 4K upscale”存在冲突。
4. HAL 中 26111 4K30/1080P60 与早期 25111 Basic 继承结论冲突；后续不能再用旧平台基线覆盖项目 HAL 设计。

## 8. 验收与性能约束

- 6GB 机型 POP Camera 后台相关进程内存占用峰值标准为 1.7GB。
- 6GB 夜景策略降为 7 帧。
- 录像滤镜仅支持 1080P30。
- 需要分别完成性能、功耗、内存/内存泄漏和稳定性专项验收。
