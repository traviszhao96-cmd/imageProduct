## 1. 背景与目标

### 问题陈述

前置摄像头默认 1x（25-26mm，含约 15% 裁切）。用户竖屏自拍时构图尚可，但横屏使用时（合影、风景自拍等），裁切后视场角明显受限，用户需手动切换到 0.8x（21-22mm）才能获得理想的广角效果。

同时，横竖屏切换时因裁切比例和屏幕方向变化，取景范围会产生感知上的"跳跃"，体验不连贯。

此外，前置焦段历史命名混乱：旧称 1.0x（实际 21-22mm）/ 1.2x（实际 25-26mm），用户和工程侧理解不一致，需借本次需求统一命名。

### 证据与数据

数据源：Phone 4a / 4a Pro，印度（2026-04-15~21，82.2 万张） + ROW（2026-03-23~29，3.5 万张）

**横竖屏比例：**
- 前置自拍以竖屏为主（67%~73%），横屏有不可忽视的占比：印度 33%、ROW 27%

**横竖屏 × 焦段交叉分析：**

| 方向 | 焦段 | 🇮🇳 印度 | 方向内占比 | 🌍 ROW | 方向内占比 |
|------|------|---------|-----------|--------|-----------|
| 竖屏 | 默认（旧 1.2x） | 446,507 | 81.09% | 20,379 | 79.20% |
| 竖屏 | 广角（旧 1.0x） | 104,121 | 18.91% | 5,351 | 20.80% |
| 横屏 | 默认（旧 1.2x） | 228,791 | 84.19% | 7,579 | 80.93% |
| 横屏 | 广角（旧 1.0x） | 42,948 | 15.80% | 1,786 | 19.07% |

横竖屏焦段分布非常接近，差异仅 2-3 个百分点。值得注意的是，**横屏广角占比甚至略低于竖屏**——说明用户在横屏时并没有更主动去切广角。这不是"不想用"，更可能是没意识到裁切、或手动切换有摩擦。横屏合影恰好是最需要广角的场景，自动切换可以消除这个摩擦。

**结论：** 横屏用户中 84%（印度）/ 81%（ROW）停留在默认焦段，且横屏广角使用率不比竖屏高。自动广角有望显著改善横屏合影体验。~20% 用户已主动使用广角，验证需求存在。

### 目标用户与场景

- 用户角色：前置摄像头用户，尤其是横屏合影、横屏自拍场景
- 核心场景：
  1. 用户横屏使用前置摄像头合影 → 自动切 0.8x 广角，容纳更多人
  2. 用户从竖屏转横屏 → FOV 自动适配，无明显压缩变化
  3. 用户手动选择焦段后 → 本次使用中不再自动切换，尊重用户意图
- 使用频率：每次横屏前置拍摄触发

### 预期收益

- 横屏合影场景无需手动缩放，即拍即用
- 横竖切换时取景范围平滑过渡，无感知跳跃
- 预期覆盖横屏前置场景中 > 80% 的拍照量（当前 84% 横屏照片停留在默认焦段）
- 统一前置焦段命名，消除跨项目理解偏差

## 3. 功能定义

### 功能描述

- 功能名称：前置自动小广角
- 一句话描述：使用前置摄像头时，根据设备横竖屏状态自动在 1x（25-26mm）/ 0.8x（21-22mm）之间切换。
- 前置仅支持 0.8x 和 1x 两个焦段，无更长变焦范围。

### 范围

**In Scope:**

- 前置摄像头，默认 1x（25-26mm）
- 横屏 → 自动切换至 0.8x（21-22mm）
- 竖屏 → 自动恢复至 1x
- 用户手动变焦后，当前相机进程内不再触发自动切换
- 相机进程被杀后重新打开 → 恢复自动切换逻辑
- 前置焦段命名统一：0.8x = 21~22mm，1x = 25~26mm
- 26111 系列机型首发

**Out of Scope:**

| 不做什么 | 原因 | 未来是否考虑 |
|---------|------|------------|
| 用户手动开关自动广角 | 功能简单、自动化程度高，无需开关 | 如用户投诉再评估 |
| 后置摄像头 | 需求仅聚焦前置场景 | 不计划 |
| 1x / 0.8x 以外的焦段自动切换 | 前置仅有两个焦段 | 不计划 |
| 第三方应用适配 | 首版先覆盖系统相机 | 可考虑 |

### 适用模式/入口

系统相机 → 前置摄像头 → 照片模式。默认触发，无额外入口。

## 4. 需求

### R1 · 横屏自动切广角

优先级：Must-have

用户竖屏使用前置时焦段为 1x。当用户旋转手机至横屏，摄像头自动切换至 0.8x，无需手动操作。切换过程应平滑自然。

如果用户打开前置时已经是横屏状态，直接以 0.8x 启动。

*正常路径：* 用户前置 1x 竖屏 → 旋转至横屏 → 自动切换至 0.8x。
*边界：* 打开前置时已是横屏 → 默认 0.8x 启动。

### R2 · 竖屏恢复 1x

优先级：Must-have

用户横屏使用 0.8x 时，旋转手机回到竖屏，摄像头自动恢复至 1x。

但如果用户在横屏时已经手动切换过焦段（从 0.8x 切到 1x），则进入手动模式，旋转回竖屏时保持 1x 不变，不触发自动切换。

*正常路径：* 用户前置 0.8x 横屏 → 旋转至竖屏 → 自动恢复至 1x。
*边界：* 用户横屏时手动从 0.8x 切至 1x → 旋转至竖屏 → 保持 1x，不自动切换。

### R3 · 手动变焦后不再自动切换

优先级：Must-have

用户一旦手动变焦（双指缩放或点击焦段按钮），表达了对当前焦段的明确意图。此时自动切换应在本次相机进程中暂停，不再根据横竖屏状态自动变更焦段。

当相机进程被杀后重新打开，自动切换逻辑恢复。这是最轻量的重置方式，不需要额外 UI。

*正常路径：* 用户手动变焦 → 旋转手机 → 焦段不变。
*边界 1：* 杀进程 → 重新打开前置 → 恢复自动切换。
*边界 2：* 手动变焦后直接退出相机（不杀进程）→ 再次打开前置时，按进程存活情况决定：若进程还活着则仍禁用手动，若已死则恢复自动。

### R4 · 前置焦段命名统一

优先级：Must-have

将前置焦段从旧的 1.0x / 1.2x 命名，统一为 0.8x / 1x，并对应到物理焦距：

- 0.8x = 21~22mm（广角端）
- 1x = 25~26mm（默认，含约 15% 裁切）

相机界面焦段切换按钮显示新命名。老项目接入后行为一致。

*正常路径：* 用户使用前置 → 焦段按钮显示 0.8x / 1x。
*边界：* 老项目接入 → 0.8x 对应 21~22mm，1x 对应 25~26mm，与 26111 行为一致。

### 兼容性要求

| ID | 要求 | 优先级 |
|----|------|--------|
| C1 | 26111 系列机型 | Must-have |
| C2 | 未来机型继承，支持回落老项目 | Should-have |

## 5. 方案说明

### 核心行为

- 竖屏 → 横屏：自动从 1x 切至 0.8x
- 横屏 → 竖屏：自动从 0.8x 切至 1x
- 用户手动变焦后：本次相机进程不再自动切换
- 相机进程重启：恢复自动切换

## 8. 埋点设计

横竖屏导致焦段切换时，上报一条事件。

| event_name | key | parameter | value 示例 | 说明 |
|------------|-----|-----------|-----------|------|
| NTCamera | front_auto_wide_switch | from_zoom | 1x / 0.8x | 切换前焦段 |
| | | to_zoom | 0.8x / 1x | 切换后焦段 |

> `from_zoom` → `to_zoom` 即可推断方向：1x→0.8x 为竖转横，0.8x→1x 为横转竖。

### 上报示例

```json
// 竖屏→横屏
{ "event_name": "NTCamera", "key": "front_auto_wide_switch", "from_zoom": "1x", "to_zoom": "0.8x" }

// 横屏→竖屏
{ "event_name": "NTCamera", "key": "front_auto_wide_switch", "from_zoom": "0.8x", "to_zoom": "1x" }
```

## 12. 附录

### A. 考虑过但放弃的方案

- **方案 A：固定 0.8x 作为前置默认焦段** — 放弃原因：1x（25-26mm）在竖屏时的构图更符合用户预期，固定 0.8x（21-22mm）在竖屏时过广
- **方案 B：提供设置开关** — 放弃原因：增加设置复杂度，功能简单且预期无争议，先不加开关
- **方案 C：保留旧焦段命名（1.0x/1.2x）** — 放弃原因：用户和工程侧长期混淆，趁此需求统一命名是最小成本的时机
