# 1. 背景与目标

### 问题陈述

当前默认 H.264，同画质下文件体积比 H.265 大约 30%，用户存储被无意义地多占用。当前编码逻辑对用户还不透明且不自洽：用户手动选择 H.265 后，视频、慢动作、延时按 H.265 录制；但视频开滤镜、或使用前后双录（预览录屏链路）时，实际输出静默回落为 H.264——用户选了 H.265，拿到的却可能是 H.264 文件。同时，默认 H.264 下开启 HLG 时，系统因 10-bit 依赖自动切换为 H.265——系统本身已默认 H.265 是更高能力的编码，默认值却仍停留在 H.264，逻辑不自洽。



### 目标用户与场景

- 全体用户：不做任何设置即获得同画质、更小体积的视频文件，默认值变更直接受益
- 主动选择编码格式的用户：自己的编码选择应在任何模式下都被一致执行，不出现静默回落

使用频率：默认值设置一次长期生效（低频接触），但实际影响每一次录制输出（高频生效）。



### 预期收益

- 新机型（26111 / 26121）开箱默认 H.265，无需用户操作
- 用户编码选择在全部模式下一致生效，不出现静默回落
- 同场景下 H.265 文件体积较 H.264 节省约 30%，画质无可感知劣化

# 2. 功能定义

### 功能描述

功能名称：视频默认 H.265 编码（Default H.265 Video Encoding）

一句话描述：26111 / 26121 新机型出厂默认编码由 H.264 改为 H.265，并使编码设置（含滤镜、前后双录等预览录屏链路）在所有模式下一致生效，不再静默回落。



### 范围

In Scope:

- 项目范围：26111 / 26121 首次上项，新机型出厂默认生效，无项目差异
- 模式范围：视频、慢动作、延时摄影、前后双录，以及视频叠加滤镜 / tuning 的场景
- 设置项保留：H.264 / H.265 可手动切换，选择永久记忆
- 录屏链路改造：滤镜、前后双录等预览录屏链路改为跟随用户编码设置，不再固定回落 H.264

Out of Scope:

| 不做什么 | 原因 | 未来是否考虑 |
|-|-|-|
| 老机型 OTA 变更默认值 | 存量机型维持现有行为，避免用户习惯被动改变 | 不考虑 |
| 编码码率标定与分布优化 | 已观察到码率分布异常（双峰行为），另行跟进，不在本期范围 | 后续版本，需提前预警 |
| 照片格式（HEIF 等）编码变更 | 本 PRD 仅覆盖视频编码 | 不考虑 |



### 适用入口

Camera settings → Video → Video encoding：High efficiency (H.265) / Most compatible (H.264)。设置为全局单一状态，视频 / 慢动作 / 延时 / 滤镜 / 双录各录制链路统一读取同一状态源。



### 交互设计稿

无 UI 变更，沿用现有编码设置项（Camera settings → Video → Video encoding），无新增设计稿依赖。



## 3. 需求

### R1 · 默认编码变更为 H.265

优先级：Must-have



26111 / 26121 出厂默认编码为 H.265，设置中保留 H.264 / H.265 选项，位置与现状一致。



正常路径：

- 新机开箱后，Camera settings → Video → Video encoding 默认选中 H.265
- 用户可随时手动切换为 H.264

边界：

- 用户切换后永久记忆，不随重启相机 / 设备、模式切换、版本升级重置
- 老机型不随 OTA 变更默认值

### R2 · 编码设置全模式一致生效（录屏链路改造）



优先级：Must-have



用户设置的编码格式在全部模式范围内一致执行，消除此前预览录屏链路（滤镜 / tuning、前后双录）静默回落 H.264 的不一致行为。



正常路径：

- 正常录制链路（视频 / 慢动作 / 延时摄影）：按用户设置编码，与现状一致
- 预览录屏链路（视频开滤镜 / tuning、前后双录）：本期改造为同样按用户设置编码，不再固定回落 H.264

边界：



- 仅改变编码格式，不改变分辨率、帧率、码率档位等其他规格
- 音频编码不受影响

### R3 · HLG 联动逻辑维持现状



优先级：Must-have



用户手动选择 H.264 且开启 HLG 时，因 10-bit 依赖自动切换为 H.265，无额外提示，行为与现状一致，不在本期改动范围。

| H.264（手动） | 前后双录 | H.264 |  |

## 4. 方案说明

### 核心行为

- 编码设置为全局单一状态，作用于 MediaCodec 层；正常录制链路与预览录屏链路（滤镜 / 双录）本期统一读取同一编码状态，消除链路差异
- HLG 的 10-bit 依赖与编码器绑定关系维持现状：H.264 + HLG 时自动切 H.265，无需额外改造
- 仅编码格式变更，不影响分辨率 / 帧率 / 码率档位选择逻辑，音频编码链路不受影响

### 验收条件

- 新机开箱默认编码为 H.265
- 视频 / 慢动作 / 延时录制输出编码与用户设置一致
- 视频开启滤镜 / tuning 录制输出编码与用户设置一致（默认 H.265）
- 前后双录录制输出编码与用户设置一致（默认 H.265）
- 手动 H.264 + 开启 HLG 时自动切换 H.265
- 切换编码后重启相机 / 设备，选择保持
- 同画质码率对比，H.265 较 H.264 节省约 30%
- 老机型 OTA 后默认值与编码行为不变
