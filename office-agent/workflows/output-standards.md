# Output Standards

This workflow defines the quality bar for user-facing office-agent outputs.

## Core Standard

Outputs should be easy to use immediately and easy to maintain later.

## Default Requirements

Most outputs should be:

- concise
- structured
- explicit about what is confirmed
- free of unnecessary filler
- suitable for direct reuse in documents, tasks, or future skills

## Structure Rules

Prefer:

- short headings when they help
- grouped sections instead of long unbroken text
- direct statements over decorative writing
- visible separation between confirmed items and open items when the distinction matters

Avoid:

- inflated prose
- redundant summaries
- repeating the same point in multiple sections
- pretending the output is final when it still depends on user confirmation

## Assumption Handling

If assumptions are necessary:

- keep them minimal
- mark them clearly
- do not hide them inside polished language

If the task is still under-defined after clarification:

- provide the best useful version
- state what remains open
- avoid blocking progress unless the risk is material

## Reusability Standard

When possible, outputs should be easy to promote into:

- a template
- a rule
- a skill
- a knowledge note
- a repeatable workflow

## Formatting Bias

For this user:

- keep formatting clean and simple
- prefer high information density over decorative layout
- use lists only when they improve scanning
- do not overcomplicate the response structure

## Final Check

Before finalizing, check:

- is the output aligned with the user's actual request?
- is it concise enough to be practical?
- is the structure strong enough for future reuse?
- are assumptions or missing inputs made visible where needed?
