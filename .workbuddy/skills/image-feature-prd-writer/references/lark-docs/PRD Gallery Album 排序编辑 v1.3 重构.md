## 二、需求背景

### 问题陈述

当前 Album 页面仅支持静态展示，图集完全按照字母顺序排列。用户无法自定义顺序，无法区分高频/低频图集，操作受限。同时全部使用大图设计，空间效率低，更多 album 无法正常显示。

### 产品/数据现状

- 现有 Album 页面：纯字母排序 + 大图布局
- 无拖拽或编辑能力
- 无大小图区域区分

### 用户场景

| 角色 | 场景 | 诉求 |
|------|------|------|
| 高频用户 | 常用图集埋在列表深处 | 将常用图集置顶到大图位置，快速访问 |
| 整理型用户 | 图集数量多，层级混乱 | 将低频图集移入小图区域，减少视觉占用 |
| 习惯型用户 | 对现有大图布局有使用惯性 | 不希望强制改版，但期望有自定义能力 |
| 效率型用户 | 图集跨越很长范围 | 通过编辑模式批量调整，而非逐张拖拽 |

## 三、假设

| 假设 | 置信度 | 证伪条件 | 验证方式 |
|------|--------|---------|---------|
| 我们相信 **用户对大图布局有使用惯性，直接改版会引发抵触**，因为改版是破坏性认知变更 | Medium | 用户研究显示大部分用户从未主动调整过大图区域 | 灰度上线后对比大图区域修改率 |
| 我们相信 **500ms 长按阈值能较好区分"浏览"和"意图操作"** | Medium | 误触率 > 10% 或用户反馈"太难触发" | 埋点统计长按成功率 |
| 我们相信 **长按拖拽（不进编辑态）能覆盖 80% 的偶发微调需求** | Medium | 数据显示 Edit 模式使用量远超长按 | 埋点对比双途径使用比例 |

## 四、需求目标

- 补齐 Album 页面的拖拽整理能力
- 支持用户自定义图集顺序
- 支持大图区域和小图区域之间自由移动图集
- 统一 Album 页面图集编辑交互规范

---

## 五、需求范围

### In Scope

- 单个图集长按并滑动 → 进入拖拽状态（途径一）
- 所有图集（除 Hide / Recently Deleted 外）支持拖拽排序
- 所有图集支持大图/小图区域间移动
- 拖拽态下显示分割线
- 拖拽过程中支持自动滚动
- 松手后立即保存排序结果
- Edit 编辑模式（途径二）：更多 → Edit，含箭头切换
- 大图/小图区域空状态占位图
- Album 页面改版：拆分为大图区域 + 小图区域 + 更多区域

### Out of Scope

| 不做什么 | 原因 | 未来是否考虑 |
|---------|------|------------|
| 批量选中后拖拽 | 增加交互复杂度，首版先验证单张 | 可考虑 |
| 拖拽到"更多"区域外（跨页面） | 无明确需求场景 | 需用户反馈 |
| 撤销/Redo 拖拽历史 | 可单张手动回拖，首版不必要 | 可考虑 |
| 拖拽动画自定义 | 用系统默认动画 | 不计划 |
| 多选批量切换大图/小图 | Edit 箭头已覆盖单张切换，批量待观察 | 可考虑 |
| Hide / Recently Deleted 参与排序 | 列表型相册，交互形态与网格型图集不同，强行统一过于复杂 | 不计划 |

## 七、需求（User Story + Gherkin）

### US-01: 长按拖拽排序（途径一）

**As a** Album 页面用户, **I want to** 长按图集后滑动拖拽到目标位置, **so that** 我能快速调整单个图集的位置，无需进入额外编辑模式。

| 属性 | 值 |
|------|---|
| 优先级 | Must-have |
| 依赖 | 排序存储 |

```gherkin
Scenario 1: 长按拖拽 + 落位保存
  GIVEN 用户在 Album 页面
  WHEN 用户长按图集超过 500ms 后滑动，将其拖至目标位置松手
  THEN 图集落位到目标位置，排序立即保存

Scenario 2: 长按未滑动 → 触发 Settings
  GIVEN 用户在 Album 页面
  WHEN 用户长按图集超过 500ms 但未发生滑动，在原位释放
  THEN 弹出 Album settings 菜单
```

### US-02: 跨区域移动

**As a** Album 页面用户, **I want to** 将图集从大图区域拖入小图区域（或反向）, **so that** 我能自由调整图集的视觉层级和访问优先级。

| 属性 | 值 |
|------|---|
| 优先级 | Must-have |
| 依赖 | 双区域布局 |

```gherkin
Scenario 1: 拖拽跨区落位
  GIVEN 用户在拖拽态下
  WHEN 用户将图集从当前区域拖入另一区域并松手
  THEN 图集移入目标区域，目标区域重排，源区域恢复

Scenario 2: 无效落位 → 回弹
  GIVEN 用户在拖拽态下
  WHEN 用户在图集无法放置的位置松手
  THEN 图集回弹到原位，不弹 toast
```

### US-03: 编辑模式（途径二）

**As a** Album 页面用户, **I want to** 进入编辑模式批量调整图集, **so that** 我能通过箭头按钮和直接拖拽高效整理大量图集。

| 属性 | 值 |
|------|---|
| 优先级 | Must-have |
| 依赖 | 更多菜单入口 |

```gherkin
Scenario 1: 进入编辑模式 + 拖拽调整
  GIVEN 用户在 Album 页面
  WHEN 用户点击更多 → Edit
  THEN 所有图集可直接拖拽（无需长按），每个图集显示箭头按钮，顶部显示 Done

Scenario 2: 箭头切换区域 + Done 保存
  GIVEN 用户在编辑模式下
  WHEN 用户点击箭头切换区域，调整完毕后点击 Done
  THEN 保存当前布局，所有图集恢复正式尺寸，退出编辑模式

Scenario 3: 返回放弃
  GIVEN 用户在编辑模式下调换了图集
  WHEN 用户按系统返回
  THEN 弹出确认「是否保存更改？」，选择放弃则丢弃全部修改

Scenario 4: 空区域占位
  GIVEN 用户在编辑模式下，大图或小图区域无任何图集
  THEN 对应区域显示占位图，提示用户可拖入
```

### 非功能需求

| 类别 | 要求 | 优先级 |
|------|------|--------|
| 性能 | 拖拽过程流畅，无明显卡顿 | Must-have |
| 兼容性 | 适配横竖屏、深色/浅色主题、不同屏幕尺寸 | Must-have |

## 八、功能说明

### 1. Album 页面改版

将图集展示拆分为大图区域与小图区域：

- **默认大图图集**：Camera / Videos / Screenshots / Favourite（共 4 个）
- **默认小图图集**：其余所有图集
- **「更多」区域**（折叠在小图区域下方）：Maps（第一）、Recent（第二），及用户自定义相册
- 以上为默认布局，用户后续可自由调整（包括 Camera / Favourite 等系统相册均可移出大图区域）
- 系统相册（Camera / Videos / Screenshots / Favourite / Maps / Recent）始终保留在 Album 页面。即使被取消 Pin，也会进入「更多」区域，不会从页面消失
- 大图区域无固定数量上限

### 2. 长按拖拽排序（不进编辑态）

**触发条件：** 用户在 Album 页面长按图集超过 500ms → 震动反馈 → 滑动 > 10dp → 拖拽态

**意图识别逻辑：**
- 长按 < 500ms → 无反应
- 长按 ≥ 500ms 且未滑动 → 释放后触发 Album settings
- 长按 ≥ 500ms 且滑动 > 10dp → 拖拽排序

**拖拽态表现：**
- 图集浮起，所有图集统一中等尺寸
- 显示上下分割线，跨越时提供位置变化反馈
- 支持自动滚动
- 松手落位后按目标区域恢复正式尺寸（大图→大尺寸，小图→小尺寸）

**保存规则：**
- 排序数据和 Pin 状态存储在本地，基于系统 Album 排序机制
- 松手成功落位 / Done → 立即保存
- 位置无变化 → 保持原顺序
- 保存失败 → 回退到上一次成功状态
- 无效落位 → 回弹动画，不弹 toast

**Pin 状态与删后重建：** 若某个图集（含已 Pin 的 More Album）被整体删除后重新创建，该图集视为新图集，Pin 状态不保留，回到 More 区域默认位置。

### 3. Edit 编辑模式

入口：Album 页面 → 更多（⋮） → Edit

**编辑模式特征：**
- 所有图集直接可拖拽（无需长按），显示中等尺寸
- 每个图集右上角箭头按钮：大图区→绿色↑，小图区→红色↓
- 卡片显示拖拽手柄（≡）
- 顶部 Done，编辑模式下无超时自动保存

**空状态：** 若大图/小图区域为空→灰色虚线边框占位图（中等尺寸）

### 4. 保存与退出（统一规则）

| 场景 | 行为 |
|------|------|
| 松手落位 / Done | 立即保存最新布局 |
| 位置无变化 | 保持原顺序 |
| 保存失败 | 回退到上一次成功状态 |
| 拖拽无效/异常中断 | 回弹动画，不弹 toast |
| 编辑模式返回 | 弹出「是否保存更改？」确认框 |

## 十二、埋点

> 只上报最终保存决策，不上报中间拖拽过程。系统相册上报名称，用户自建相册只报数量不报名以保护隐私。

| event_name | event_description | parameter_name | parameter_value | value_note |
|------------|-------------------|---------------|----------------|------------|
| album_reorder | 用户保存排序结果 | pinned | camera,videos,screenshots,favourite | 已置顶的系统相册名单，逗号分隔，按实际顺序 |
| album_reorder | 用户保存排序结果 | unpinned | maps,recent | 未置顶的系统相册名单，逗号分隔，按实际顺序 |
| album_reorder | 用户保存排序结果 | pinned_user_count | 0, 1, 2, … | 已置顶的用户自建相册数量 |
| album_reorder | 用户保存排序结果 | unpinned_user_count | 0, 1, 2, … | 未置顶的用户自建相册数量 |
| album_reorder | 用户保存排序结果 | source | drag / edit | drag=长按拖拽落位保存，edit=Edit 模式 Done 保存 |
